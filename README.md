# ArpiDent — онлайн-запись в стоматологическую клинику

Я разработала учебное веб-приложение для записи пациентов на приём. На сайте можно выбрать услугу, врача и свободное время, оформить запись, войти в личный кабинет и отменить собственную запись. В отдельной панели администратор просматривает заявки и управляет их статусами.

## Возможности

- Каталог врачей и услуг с поиском и фильтрами.
- Проверка свободных интервалов, защита от повторной записи на занятое время.
- Регистрация и вход пациента; просмотр только собственных записей.
- Отмена записи пациентом и изменение статусов администратором.
- Отзывы, выбор врача и услуги.
- Отдельная админ-панель с поиском и фильтрами.
- Сохранение данных в локальный JSON-файл.

## Стек

JavaScript, HTML, CSS, Node.js 20+, HTTP API, JSON, встроенный тестовый модуль `node:test`. Внешних npm-зависимостей нет.

## Запуск

В корне проекта:

```bash
npm start
```

Сайт: `http://localhost:3000`. Админ-панель: `http://localhost:3000/admin`.

Для доступа администратора при запуске нужно задать собственные переменные окружения:

```bash
ADMIN_LOGIN='owner' ADMIN_PASSWORD='your-long-unique-password' npm start
```

Пароль администратора должен состоять не менее чем из 12 символов. Предустановленных действующих учётных данных администратора нет. Если переменные не заданы, административный вход отключён.

Файл `db.json` создаётся автоматически и не загружается в Git. Чтобы изменить расположение базы, можно задать `DB_PATH` (полный путь). Содержимое файла — демонстрационные данные, а не база настоящей клиники.

## Проверка

```bash
npm test
```

Тесты проверяют создание сессий, хранение паролей, разграничение доступа пациентов и администратора, запись на приём, запрет дублирования времени и отмену. Для тестов используется временная база, поэтому рабочий `db.json` не изменяется.

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка сервера |
| GET | `/api/doctors` | Каталог врачей |
| GET | `/api/services` | Каталог услуг |
| GET | `/api/slots?doctorId=1&date=2026-12-15` | Свободные интервалы |
| POST | `/api/users/register` | Регистрация пациента |
| POST | `/api/users/login` | Вход пациента |
| GET | `/api/users/me` | Текущий пациент |
| POST | `/api/admin/login` | Вход администратора |
| GET | `/api/admin/session` | Проверка администраторской сессии |
| POST | `/api/logout` | Выход |
| POST | `/api/bookings` | Новая запись |
| GET | `/api/bookings` | Записи текущего пациента или все записи для администратора |
| PATCH | `/api/bookings/:id/status` | Пациент: отмена своей записи; администратор: управление статусом |
| DELETE | `/api/bookings/:id` | Отмена записи с проверкой прав |
| GET, POST | `/api/reviews` | Просмотр и добавление отзывов |

## Как работает защита доступа

После входа сервер выдаёт случайный токен сессии в cookie `HttpOnly` и `SameSite=Strict`. На HTTPS дополнительно используется `Secure`. Сервер проверяет права на каждом запросе, поэтому изменение `userId` в браузере не позволяет читать чужие записи. Пароли пациентов хранятся в виде хешей scrypt с индивидуальной солью; старые пароли мигрируют при чтении базы. Учётные данные администратора берутся из переменных окружения.

## Ограничения

Это прототип, не медицинская информационная система. JSON-файл не рассчитан на параллельные серверы и надёжное хранение реальных медицинских данных; сессии пока хранятся в памяти процесса и сбрасываются после рестарта. Для промышленного применения понадобятся полноценная СУБД, транзакции, постоянное хранилище сессий, резервное копирование, мониторинг, контроль нагрузки и аудит защиты персональных данных. Без этих доработок реальные данные пациентов в систему вносить нельзя.
